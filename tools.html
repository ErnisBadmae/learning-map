Выбор инструмента: от выхода к модели

Три вопроса — они выбирают инструмент
  1. Что на выходе? одна метка из N → мультикласс (softmax + CE) · да/нет → бинарная (сигмоида + BCE = логрег) · несколько меток сразу → мультилейбл (N сигмоид + BCE) · число → регрессия (линрег, MSE/MAE) · уровень 1–5 → порядковая · список → ранжирование · поля из текста → извлечение · свободный текст → генерация
  2. Сколько выходов у одного входа? Больше одного → один общий энкодер и голова на каждый выход, лоссы складываются с весами.
  3. Какой вход? Таблица → бустинг. Текст → TF-IDF, потом энкодер. Несколько модальностей → энкодер на каждую, потом слияние.

Кейсы

КейсВыход → типБейзлайн и почемуML: инструментМетрика
Тема обращения одна из N → мультикласс ключевые слова → TF-IDF + логрег: слова часто решают энкодер + softmax, CE — если много перефразов macro-F1
Тема + срочность + эскалация 3 выхода на один текст → энкодер с 3 головами правила + 3 отдельных логрега на TF-IDF один энкодер: softmax / сигмоида / сигмоида, сумма лоссов с весами; текст кодируется один раз своя на каждую голову
Типы событий в новости (кейс 3) дивиденды и суд одновременно → мультилейбл словарь на каждый тип / логрег по каждой метке на TF-IDF энкодер + N сигмоид, BCE; порог на каждую метку PR по каждой метке
Срочность 1–5 уровни с порядком → порядковая правила по словам регрессия с округлением или K−1 бинарных «> k»; не softmax — иначе 1 и 5 «одинаково далеки» MAE, взвешенная каппа
Нагрузка на операторов завтра число → регрессия «как неделю назад»: сезонность сильная линрег на лагах → бустинг на лагах и календаре MAE, MAPE
Фрод по операции да/нет по таблице → бинарная, бустинг правила + логрег: интерпретируемо бустинг; каскад: правила → бустинг → человек на сером пороге recall при заданном precision, PR-AUC
Модерация с человеком (М5) да/нет + к человеку → бинарная + 2 порога стоп-слова энкодер → калибровка → выше порога блок, ниже пропуск, середина — человеку precision автоматики, нагрузка на людей
Ответ из базы знаний список документов → ранжирование BM25 каскад: bi-encoder отбирает 100 → cross-encoder переставляет топ → LLM отвечает по найденному Recall@k, NDCG@10, faithfulness
Рекомендация продукта УК (кейс 5) лучший продукт или ничего → ранжирование / uplift популярное среди пригодных фильтр пригодности кодом → бустинг на каждый продукт → uplift (T-learner) Qini, приток против контроля
«Продай половину Сбера» (кейс 4) поля → извлечение, не классификация регулярки + словарь тикеров LLM со схемой JSON + намерение (мультикласс); лоты считает код точное совпадение полей
Документы на квал (кейс 6) тип + поля → мультикласс + извлечение OCR + регулярки по типу классификатор типа → OCR / VLM в схему → проверки кодом; решение принимает код, не модель точность по полю
Обращение со скриншотом и голосом вход из 3 модальностей всё в текст: ASR + OCR → текстовая модель энкодер на каждую модальность → слияние → те же головы как у текстовой модели
Агент: какой шаг делать следующее действие → маршрутизация конечный автомат + правила классификатор намерения → LLM-роутер только на неуверенных доля верных маршрутов, pass^k
Дубли обращений пара похожа / нет MinHash по тексту эмбеддинги + косинус, порог по разметке precision при пороге

Что путается

  • Лестница ≠ каскад. Лестница — порядок разработки: правила → TF-IDF + логрег → энкодер → LLM; следующую ступень берёшь, только если предыдущая не прошла приёмку. Каскад — порядок в проде на одном запросе: дешёвая модель сначала, дорогая модель или человек — только на неуверенных.
  • Логрег — не слой поверх голов. Бинарная голова (линейный слой + сигмоида) и есть логрег над вектором энкодера. Линрег — когда на выходе число, а не вероятность.
  • Эмбеддинг 768 при сотне примеров на класс — признаков больше, чем данных: PCA до 64–128 + регуляризованный логрег, а бустингу — не сырой вектор, а прогноз модели над ним.
