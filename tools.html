Выбор инструмента: от выхода к модели

Техсекция: Python, SQL, ряды →КейсыЧто путаетсяЛоссыДеревьяВопросы про лес
Три вопроса — они выбирают инструмент
  1. Что на выходе? одна метка из N → мультикласс (softmax + CE) · да/нет → бинарная (сигмоида + BCE = логрег) · несколько меток сразу → мультилейбл (N сигмоид + BCE) · число → регрессия (линрег, MSE/MAE) · уровень 1–5 → порядковая · список → ранжирование · поля из текста → извлечение · свободный текст → генерация
  2. Сколько выходов у одного входа? Больше одного → один общий энкодер и голова на каждый выход, лоссы складываются с весами.
  3. Какой вход? Таблица → логрег / случайный лес → бустинг. Текст → TF-IDF, потом энкодер. Несколько модальностей → энкодер на каждую, потом слияние.

Маршрутизация чата

«Аналитикам нужно из новостей вытаскивать, что произошло: дивиденды, суд, сделка, смена CEO. В одной новости бывает несколько событий.»		 дивиденды и суд одновременно → мультилейбл словарь на каждый тип / логрег по каждой метке на TF-IDF энкодер + N сигмоид, BCE; порог на каждую метку precision и recall по каждой метке (и порог на каждую: среднее прячет провал на редкой)
Приоритет в очереди
«Оцени срочность обращения по шкале от 1 до 5, чтобы выстроить очередь операторов.»		 уровни с порядком → порядковая правила по словам регрессия с округлением или K−1 бинарных «> k»; не softmax — иначе 1 и 5 «одинаково далеки» MAE (средний промах в уровнях: 1↔5 хуже, чем 2↔3), взвешенная каппа (согласие с разметкой за вычетом случайного; дальний промах штрафуется сильнее)
Планирование смен
«Контакт-центр планирует смены: предскажи, сколько обращений придёт завтра по часам.»		 число → регрессия «как неделю назад»: сезонность сильная линрег на лагах → бустинг на лагах и календаре; деревья (лес, бустинг) не экстраполируют рост — тренд снимают линрегом или учат на разностях MAE (средний промах в обращениях — сколько операторов лишних или не хватит), MAPE (тот же промах в % — сравнимо между днями разного объёма)
Антифрод переводов
«Найди мошеннические операции по картам. Решение нужно за 100 мс, пока идёт платёж.»		 да/нет по таблице → бинарная, бустинг правила + логрег: интерпретируемо; случайный лес — сильный бейзлайн без настройки бустинг; каскад: правила → бустинг → человек на сером пороге recall при заданном precision (precision фиксируем — ложная блокировка злит клиента; растим долю пойманного фрода), PR-AUC (качество по всем порогам при дисбалансе; ROC-AUC при 0,1% фрода обманчиво высокий)
Отток клиентов
«Предскажи, кто из клиентов брокера уйдёт в ближайший месяц: у отдела удержания бюджет на 5 тыс. звонков.»		 уйдёт / нет по таблице → бинарная правило «нет сделок 60 дней» → логрег → случайный лес: нелинейности и взаимодействия без настройки, важность признаков бустинг (CatBoost — категориальные как есть); честнее — uplift: звонить тем, кого звонок удержит, а не тем, кто уйдёт в любом случае precision в топ-5000 (бюджет фиксирован — важно, сколько из обзвоненных реально собирались уйти), PR-AUC (уходит мало, классы несбалансированы)
Кредитный скоринг
«Решай, одобрять ли кредит: анкета, кредитная история, обороты по счёту. Решение надо объяснить клиенту и регулятору.»		 вероятность дефолта → бинарная, нужна калиброванная вероятность логрег на биннинге признаков (скоркарта): объясним по баллам, регулятор привык бустинг + калибровка + объяснение (SHAP); лес хуже: его вероятности сжаты к середине, без калибровки в цену кредита их не взять Gini (= 2·ROC-AUC − 1, банковский стандарт: насколько хорошо ранжирует плохих выше хороших), калибровка (прогноз 5% должен означать 5% дефолтов — от этого ставка и резервы)
Модерация отзывов
«Отзывы и комментарии в соцсетях банка: прятать оскорбления и спам, спорное отдавать модераторам.»		 да/нет + к человеку → бинарная + 2 порога стоп-слова энкодер → калибровка → выше порога блок, ниже пропуск, середина — человеку precision автоматики (из решённого без человека сколько верно — там ошибку никто не поймает), нагрузка на людей (доля в серой зоне — столько модераторов нужно)
Ассистент по базе знаний
«Операторы долго ищут ответы в базе знаний. Сделай ассистента, который отвечает на вопрос со ссылкой на документ.»		 список документов → ранжирование BM25 каскад: bi-encoder отбирает 100 → cross-encoder переставляет топ → LLM отвечает по найденному Recall@k (нужный документ попал в топ-k — иначе реранкер и LLM его не увидят), NDCG@10 (верное стоит выше в топ-10, позиция учитывается), faithfulness (доля утверждений ответа, подтверждённых найденным, — против выдумок)
Персональное предложение
«В приложении брокера есть место под один баннер. Предлагай клиенту фонд или стратегию так, чтобы росли вложения.»		 лучший продукт или ничего → ранжирование / uplift популярное среди пригодных фильтр пригодности кодом → бустинг на каждый продукт → uplift (T-learner) Qini (сколько дополнительных покупок дал показ тем, кого модель выбрала первыми, — меряет прирост, а не отклик), приток против контроля (деньги в группе показа минус в группе без показа — бизнес-эффект)
Торговый агент
«Клиент пишет или говорит «продай половину Сбера» — агент должен выставить заявку на бирже.»		 поля → извлечение, не классификация регулярки + словарь тикеров LLM со схемой JSON + намерение (мультикласс); лоты считает код точное совпадение всех полей (поручение верно только целиком: ошибка в бумаге или объёме — неверная сделка)
Проверка документов
«Клиент загружает сканы дипломов и выписок, чтобы получить статус квалифицированного инвестора. Сейчас сотрудники проверяют руками несколько дней.»		 тип + поля → мультикласс + извлечение OCR + регулярки по типу классификатор типа → OCR / VLM в схему → проверки кодом; решение принимает код, не модель точность по каждому полю (после нормализации; по полю видно, где нужен человек)
Обращения разных форматов
«В поддержку приходят тексты, голосовые и скриншоты ошибок. Определи тему обращения.»		 вход из 3 модальностей всё в текст: ASR + OCR → текстовая модель энкодер на каждую модальность → слияние → те же головы как у текстовой модели + отдельно по каналам (голос и скриншоты проседают из-за ошибок ASR и OCR)
Агент поддержки
«Сделай агента, который сам решает: ответить, уточнить, сделать действие (перевыпустить карту) или позвать оператора.»		 следующее действие → маршрутизация конечный автомат + правила классификатор намерения → LLM-роутер только на неуверенных доля верных маршрутов (шаг выбран правильно), pass^k (задача решена во всех k повторах — агент надёжен, а не угадал)
Склейка дублей
«Клиент пишет об одной проблеме в чат, почту и приложение. Склей дубли, чтобы оператор не делал работу трижды.»		 пара похожа / нет MinHash по тексту эмбеддинги + косинус, порог по разметке precision при пороге (из склеенных как дубли сколько настоящих — ложная склейка теряет обращение)

Что путается

  • Лестница ≠ каскад. Лестница — порядок разработки: правила → TF-IDF + логрег → энкодер → LLM; следующую ступень берёшь, только если предыдущая не прошла приёмку. Каскад — порядок в проде на одном запросе: дешёвая модель сначала, дорогая модель или человек — только на неуверенных.
  • Логрег — не слой поверх голов. Бинарная голова (линейный слой + сигмоида) и есть логрег над вектором энкодера. Линрег — когда на выходе число, а не вероятность.
  • Эмбеддинг 768 при сотне примеров на класс — признаков больше, чем данных: PCA до 64–128 + регуляризованный логрег, а бустингу — не сырой вектор, а прогноз модели над ним.

Функции ошибки (лоссы)

Одна идея на всё семейство кросс-энтропии: штраф тем больше, чем меньшую вероятность модель дала правильному ответу: −log(p верного). Дала 0,81 — штраф 0,21; дала 0,04 — штраф 3,2. Уверенная ошибка наказывается сильнее всего.

Лосс ≠ метрика. Лосс — то, что модель минимизирует при обучении: он должен быть гладким, чтобы считать градиент. Метрика — то, чем меряем результат (F1, recall при пороге): её часто нельзя оптимизировать напрямую. Учим CE, меряем macro-F1.

кросс-энтропия, categorical cross-entropy		 одна метка из N, классы исключают друг друга softmax: N вероятностей, в сумме 1 −log(p верного класса) тема обращения: «остатки» получили 0,81 → штраф 0,21
BCE
binary cross-entropy, бинарная кросс-энтропия; у логрега это log-loss		 да/нет; или несколько независимых меток (мультилейбл) — BCE по каждой и сумма сигмоида: одно число от 0 до 1 на метку −[y·log p + (1−y)·log(1−p)], y — правда (0 или 1), p — вероятность «да» срочность: p = 0,73, правда «срочно» → 0,31; правда «не срочно» → 1,31
BCE с весом класса дисбаланс: положительных 1–5% сигмоида та же BCE, но ошибка на редком классе умножается на вес (например, на долю отрицательных / долю положительных) антифрод: пропуск фрода стоит в 50 раз дороже — вес 50
Focal loss сильный дисбаланс и много лёгких отрицательных сигмоида −(1−p)^γ · log p, обычно γ = 2: уверенно верные примеры почти не дают штрафа, обучение идёт на трудных фрод: 99% операций очевидно чистые — focal не даёт им забить градиент
InfoNCE
контрастивный лосс		 учим эмбеддинги и поиск: есть пары «запрос — подходящий документ», а не классы вектор; сходство (косинус) с документами батча CE, где «классы» — документы в батче: −log( e^(s₊/τ) / Σ e^(sⱼ/τ) ); s₊ — сходство с правильным, τ — температура (меньше — жёстче к похожим негативам) запрос «остаток по счёту», в батче 64 документа, один правильный — он должен получить наибольшее сходство
Pairwise / BPR
лосс ранжирования по парам		 важен порядок, а не значение: рекомендации, выдача скор на объект −log σ(s₊ − s₋): купленный товар должен получить скор выше некупленного лента: фонд, в который вложились, выше показанного без отклика
MSE
среднеквадратичная ошибка		 число на выходе (регрессия), выбросов мало одно число, без активации (y − ŷ)²: большие промахи штрафуются квадратично, оптимум — среднее нагрузка: промах на 100 обращений в 100 раз хуже промаха на 10
MAE / Huber число, но есть выбросы одно число MAE |y − ŷ|, оптимум — медиана, выброс не тянет прогноз. Huber — квадрат вблизи нуля и модуль на больших промахах суммы переводов: один перевод на 50 млн не должен сдвигать всю модель
Квантильный
pinball loss		 нужен прогноз с запасом, недобор дороже перебора одно число для квантиля q: недобор штрафуется весом q, перебор — (1−q). При q = 0,9 недобор в 9 раз дороже смены операторов: лучше выйти лишним, чем оставить очередь
Шпаргалка в одну колонку: одна из N → softmax + CE · да/нет → сигмоида + BCE · метки вместе → N сигмоид + BCE · дисбаланс → BCE с весом или focal · пары запрос-документ → InfoNCE · порядок → pairwise · число → MSE (выбросы — MAE/Huber, запас — квантильный) · несколько голов → сумма лоссов голов с весами.

Деревья с нуля

  • Решающее дерево — цепочка вопросов «признак ≤ порог?». Каждый ответ ведёт вниз, в листе — ответ: доля класса (классификация) или среднее (регрессия). Пример для кредита: «доход ≤ 50 тыс.?» → да → «были просрочки?» → да → лист «дефолт 60%».
  • Как дерево выбирает вопрос. Перебирает все признаки и все пороги и берёт разбиение, после которого группы чище. Чистоту меряют Gini = 1 − Σp² (или энтропией): группа 50/50 → 0,5; 90/10 → 0,18; один класс → 0. Для регрессии — насколько упала MSE.
  • Расчёт на числах. 10 заёмщиков, 5 дефолтов: Gini = 0,5.
    Вопрос «были просрочки?»: слева 4 (3 дефолта) → Gini 0,375; справа 6 (2 дефолта) → 0,444; взвешенно 0,4·0,375 + 0,6·0,444 = 0,417 → выигрыш 0,08.
    Вопрос «доход ≤ 50 тыс.?»: слева 5 (4 дефолта) → 0,32; справа 5 (1 дефолт) → 0,32; взвешенно 0,32 → выигрыш 0,18. Берём доход и повторяем то же в каждой половине.
  • Почему одно дерево плохо. Глубокое запоминает выборку: возьми другие 1000 клиентов — дерево выйдет совсем другим (высокий разброс, variance). Мелкое — грубое, не видит закономерностей (высокое смещение, bias). Ансамбли решают одну из двух проблем.
  • Бэггинг. Из выборки N объектов делаем бутстреп — выборку того же размера с возвращением (часть объектов повторится, ~37% не попадут). На каждой учим глубокое дерево, ответы усредняем. Каждое дерево переобучено по-своему, ошибки взаимно гасятся — разброс падает.
  • Случайный лес = бэггинг + в каждом разбиении дерево выбирает только среди случайного подмножества признаков (max_features, обычно √p). Иначе все деревья начинают с самого сильного признака и выходят похожими, а среднее похожих почти не снижает разброс.
  • Градиентный бустинг. Мелкие деревья (глубина 3–8) строятся по очереди: каждое учится предсказывать ошибку суммы предыдущих. Пример: правда 100. Старт — среднее 70, ошибка 30. Дерево 2 учит 30, добавляем с шагом η = 0,5 → 85, ошибка 15. Дерево 3 → 92,5… Так падает смещение. «Градиентный» — потому что для любого лосса «ошибка» — это антиградиент лосса по прогнозу; для MSE это обычный остаток y − F.

Вопросы техсекции про случайный лес

Типовые вопросы. Нажми на вопрос — откроется ответ. Сначала ответь вслух сам.

Чем случайный лес отличается от градиентного бустинга?Лес — бэггинг: глубокие деревья независимо на бутстреп-выборках со случайными признаками, ответы усредняются, снижается разброс. Бустинг — мелкие деревья по очереди, каждое учит ошибку суммы предыдущих, снижается смещение. Бустинг обычно точнее на таблицах, но требует настройки и early stopping.
Почему лес не переобучается от увеличения числа деревьев?Ответ леса — среднее по деревьям. С ростом числа деревьев среднее просто стабилизируется к своему пределу: ошибка на тесте выходит на плато и не растёт. Переобучение леса зависит от глубины и размера листьев, а не от числа деревьев. У бустинга иначе: каждое новое дерево подгоняет остатки, и в какой-то момент — уже шум.
Почему усреднение деревьев снижает разброс? Есть формула?Дисперсия среднего B деревьев с дисперсией σ² и корреляцией ρ между ними: ρσ² + (1−ρ)σ²/B. Второе слагаемое уходит с ростом B, первое — нет. Поэтому важно не только много деревьев, но и низкая корреляция между ними — для этого случайные признаки.
Зачем выбирать случайное подмножество признаков в каждом разбиении?Чтобы деревья были разными (низкая ρ в формуле выше). Если есть один сильный признак, без ограничения все деревья ставят его в корень и выходят похожими. Если max_features = все признаки, лес превращается в обычный бэггинг деревьев.
Что такое бутстреп и OOB-оценка? Сколько объектов не попадает в выборку дерева?Бутстреп — выборка того же размера с возвращением. Вероятность, что объект не попал: (1 − 1/N)^N → 1/e ≈ 37%. Эти объекты — out-of-bag для дерева: на них дерево можно проверить. Усреднив по всем деревьям, получаем OOB-оценку качества без отдельной валидации.
Почему в лесу деревья глубокие, а в бустинге мелкие?Лес гасит разброс усреднением, поэтому ему нужны деревья с маленьким смещением — глубокие, пусть и переобученные. Бустинг гасит смещение последовательными поправками, поэтому ему нужны слабые деревья с маленьким разбросом — мелкие.
Какие гиперпараметры у леса и что настраивать первым?n_estimators — больше лучше, пока хватает времени (300–1000). max_features — главный для качества (√p для классификации, p/3 для регрессии как старт). max_depth / min_samples_leaf — против переобучения на шумных данных. class_weight — при дисбалансе.
Как лес считает важность признаков и в чём подвох?По умолчанию (MDI) — сумма уменьшения Gini от разбиений по признаку. Подвох: завышает признаки с множеством значений (ID, непрерывные суммы), у них больше порогов для случайно удачного разбиения; считается на трейне. Коррелированные признаки делят важность между собой. Надёжнее permutation importance на валидации (перемешали признак — насколько упало качество) или SHAP.
Может ли случайный лес экстраполировать?Нет. Прогноз — среднее значений из листьев, то есть из обучающих данных. Если в обучении цены были до 100, лес никогда не предскажет 150, даже при явном росте. Для трендов: линейная модель на тренд, а лес на остатки, или учить на разностях.
Нужно ли нормировать признаки для леса?Нет. Дерево смотрит только порядок значений («≤ порог»), поэтому любое монотонное преобразование (логарифм, масштаб) разбиений не меняет. Для логрега и нейросетей нормировка нужна.
Как лес работает с категориальными признаками и пропусками?В sklearn категории надо кодировать. One-hot для признака с сотнями значений плох: дерево видит много слабых бинарных столбцов. Лучше target encoding с расчётом вне фолда (иначе утечка) или CatBoost. Пропуски — импутация или флаг «был пропуск» как отдельный признак; в новых версиях sklearn лес умеет пропуски сам.
Калиброваны ли вероятности леса?Нет: вероятность — средняя доля класса в листьях, а деревья редко единодушны, поэтому прогнозы сжаты к середине — редко бывают близко к 0 или 1. Если по вероятности считается цена или порог, калибруем на отложенной выборке: Platt (логрег поверх) или изотоническая регрессия.
Как бороться с дисбалансом классов в лесу?class_weight="balanced_subsample" (веса пересчитываются на каждой бутстреп-выборке), балансированный бутстреп (поровну классов в каждой выборке), и главное — порог не 0,5, а подобранный по PR-кривой под нужный precision или recall.
Когда лес лучше бустинга?Мало данных или шумные метки (бустинг подгоняет шум); нужен результат без настройки; нужна параллельная быстрая обучаемость; нужна честная оценка без валидации (OOB). Когда данных много и есть время на тюнинг — обычно выигрывает бустинг.
Что с задержкой и памятью у леса в проде?Инференс — проход по каждому дереву: время ~ число деревьев × глубина. 500 глубоких деревьев — сотни мегабайт и медленно для 10 мс на запрос. Решения: меньше деревьев и ограничение глубины, компиляция деревьев (Treelite, ONNX), либо переход на бустинг — у него мелкие деревья.
